# 《蛊箓》项目开发交接说明（给接手 AI）

## 1. 项目是什么

本地运行的《蛊真人》小说知识库 Web 应用：问答（RAG）+ 阅读（原版txt/插图版PDF/人祖传/资料合集）+ 百科 + 游戏 + 设置。
技术栈：Python 3.13 + FastAPI + 零构建原生前端（多文件静态资源，无框架、无构建）+ 本地向量库 + OpenAI 兼容 API。

## 2. 启动方法

\`\`\`bash
cd gu-zhen-ren-rag
pip install -r requirements.txt
uvicorn app.main:app --port 8000
# 浏览器打开 http://localhost:8000
\`\`\`

## 4. ★ 连接 AI（OpenAI 兼容服务）是怎么实现的

### 调用链路（一次问答的完整流程）

1. 前端 \`app/static/app.js\` 的 \`ask()\` 函数：用户点发送 → \`POST /api/ask\`，参数 \`{question, scope, history, web_fallback}\`
2. 后端 \`app/main.py\` 的 \`ask()\`：问题中的百科词条名强制召回 + 调 \`retriever.search()\` 检索相关片段（正文/设定/摘要/百科四子库，RRF 融合取 top-5）
3. \`app/rag.py\` 的 \`build_prompt()\`：把检索到的片段 + 问题拼成给 AI 的 prompt
4. \`app/rag.py\` 的 \`ask_llm()\`（或带联网的 \`_chat_web\` / \`ask_llm_web\`）：用 openai SDK 调用配置的兼容服务，拿到回答；资料库答不了时自动联网搜索；回答要点还会反哺二次检索，命中章节再整合
5. 返回 \`{answer, sources, cost_rmb, web, wiki_cites}\`，前端渲染回答 + 来源卡片

### DeepSeek 调用的具体代码（app/rag.py 的 ask_llm）

\`\`\`python
def ask_llm(system, user, api_key, base_url, model, history=None):
    from openai import OpenAI
    client = OpenAI(api_key=api_key, base_url=base_url)
    messages = [{"role": "system", "content": system}]
    for h in (history or [])[-8:]:  # 多轮追问上下文
        messages.append({"role": h["role"], "content": h["content"]})
    messages.append({"role": "user", "content": user})
    resp = client.chat.completions.create(model=model, messages=messages, temperature=0.4, max_tokens=1024)
    return resp.choices[0].message.content or ""
\`\`\`

### API Key 从哪来

- \`app/config.py\`：启动时从项目根目录 \`.env\` 读取 \`AI_API_KEY\`、\`AI_BASE_URL\`、\`AI_MODEL\`；未设置时兼容旧版 \`DEEPSEEK_*\` 变量
- 网页「设置」页提交 Base URL、Key 和模型名：先调用 \`POST /api/settings/test\` 测试，成功后调用 \`POST /api/settings\` 写回 \`.env\`，无需重启；Key 留空会沿用已有值
- **没有 Key 时**：\`/api/ask\` 返回 mock 结果（只显示检索到的来源，不调 AI），前端显示“测试模式”提示
- 默认连接 DeepSeek 的 \`deepseek-chat\`，也可配置 OpenAI、硅基流动、火山方舟或本地 Ollama 等兼容服务

### 检索（prompt 里喂什么）

- 混合检索：固定 Jina 中文增强模型的稠密向量 top-20 + BM25 关键词 top-20 → RRF 融合 → 取前 5 个片段（项目不再支持切换检索模型）
- 每个片段：章节标题 + 正文前 600 字
- 正文片段带「第N卷·第N章·标题」标签，prompt 要求 AI 利用章节标题回答「首次出现」类问题

## 5. 前端 UI 修改注意事项

- HTML 结构在 \`app/static/index.html\`，主交互在 \`app/static/app.js\`，样式分 \`app.css\`（基础）/ \`refine.css\`、\`ink.css\`（视觉覆盖），百科页在 \`wiki-browser.js\` / \`wiki-browser.css\`；改完浏览器 Ctrl+F5 刷新即可（服务已对静态资源加 no-cache 头）
- 无任何前端框架/CDN 依赖（仅本地 pdfjs），保持零构建
- 5 个 tab：问答 / 阅读 / 百科 / 游戏 / 设置，对应 \`<section id="tab-*">\`
- 阅读区的三套目录（原版/插图版/资料合集）都用 \`<details>\` 折叠树，交互已统一
- PDF 阅读用 PDF.js canvas 渲染（\`renderChapter()\`），章节内连续滚动 + 上一章/下一章
- 主题色变量在 \`:root\`（--bg / --card / --accent / --accent2 等）

## 6. 不要动的东西

- \`data/\`、\`data_jina2/\`：预建向量库和缓存数据，改 UI 不需要动
- 原始小说文件在项目**外**一层（\`../gu-zhen-ren\` txt、\`../gu_zhen_ren_pdf\` PDF、\`../gu-zhenren-lore\` docx），阅读功能实时读它们；只优化 UI 不需要碰
- \`.env\`：含用户 API Key，不要提交/不要写死
