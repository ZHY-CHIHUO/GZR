# 📜 蛊箓 · 蛊真人维基百科

> **v1.0.0 · Jina 离线版**｜本地部署、数据自管、资料可分享。

基于《蛊真人》全文（2334 章 + 序）+ 书友设定合集（约 40 万字）的**本地知识库 + 百科 + 游戏**网页应用。
**自带预建 Jina 中文增强向量索引；源码版首次语义检索会下载本地模型，便携版已内置模型。问答支持任意 OpenAI 兼容服务（不配 Key 也能用百科/阅读/游戏/检索测试）。**

## 功能模块

### 首页

提供统一搜索入口。输入人物、蛊虫、剧情或设定关键词，即可转到问答模块检索；常用角色也可一键发起提问。

### 问答与检索

- 同时检索原著正文、书友设定、章节摘要和百科词条；使用 Jina 中文向量检索与 BM25 关键词检索，经 RRF 融合排序。
- 固定使用 `jina-v2-base-zh`，使本地资料、来源卡片和问答结果始终对应同一套向量索引。
- 支持多轮追问、检索范围切换（全部资料 / 仅原著正文），并会强制召回问题中出现的百科词条。
- 支持“首次出现”精确全文查找和正则表达式，可按卷、章顺序定位台词、词句或剧情；来源卡片可直接打开命中的原文或资料段落。
- 未配置 API Key 时可使用检索测试模式；配置任意 OpenAI 兼容服务后，可基于资料生成 AI 回答。
- 可在设置中开启联网搜索兜底。网络回答会单独标注并附参考来源。

### 阅读

- **原版小说**：按卷、章阅读全文，支持关键词、正则表达式和仅限当前卷搜索。
- **插图版**：通过内置 PDF 阅读器查看插图版《蛊真人》。
- **人祖传**：在线阅读《人祖传》全文。
- **资料合集**：查看书友整理的世界观、人物、势力、蛊虫、杀招等设定资料。

### 百科

- 收录 `2627` 条结构化词条，支持分类浏览、搜索、详情查看和一键“问 AI”。
- 支持新增、编辑、改名、调整分类和删除词条；删除内容进入回收站，可恢复或彻底删除。
- 编辑百科后可在设置中重建语义索引，让新词条参与问答检索。

### 游戏

- **选择题**：内置 `693` 题，支持混合题库、蛊虫、人物和蛊虫类型分类。
- **猜谜**：内置 `491` 道猜蛊虫、猜人物和猜物品谜题，根据多条提示逐步作答。
- 支持新增自定义题目、批量导入 JSON 题库和查看答题历史记录。

### 设置与资料管理

- 填写、测试和保存任意 OpenAI 兼容服务的 Base URL、API Key 与模型名。
- 开关联网搜索，查看 Jina 检索模型状态，或在资料变更后重建百科索引。
- 导出、导入资料包或完整离线包；导入前会显示文件清单和冲突预览，合并导入保留本地冲突，覆盖导入会自动备份。

## 快速开始（新手 3 分钟）

> 不用懂任何命令：**装一次 Python，之后每次双击一个文件就能用。**

### 第 1 步：安装 Python（只装一次）

1. 打开 <https://www.python.org/downloads/> ，点黄色大按钮下载；
2. 双击安装包，**务必勾选** “Add Python to PATH”（加入系统路径），再一路点 Next；
3. 装完即可，以后不用再管它。

> 不确定装没装过？直接做第 2 步，脚本会帮你检查并提示。

### 第 2 步：双击启动

1. 把项目文件夹放到任意位置（路径里**不要有中文**，例如 `D:\gzr`）；
2. 双击项目根目录的 **`一键启动.bat`**；
3. 第一次运行会自动完成三件事（约 3 分钟，需要联网）：
   - 创建运行环境；
   - 安装依赖；
   - 首次进行语义检索时下载约 614MiB 的 Jina 中文模型（只需一次）。
4. 以后每次使用，双击同一个文件，几秒就打开。

### 第 3 步：开始使用

- 浏览器会自动打开 **http://127.0.0.1:8000**（没自动打开就手动输入这个地址）；
- **不填任何 Key 也能用**：百科、阅读器、小游戏、检索测试（能看到每个问题命中了哪些章节）；
- 想让 AI 真正回答问题：页面右上角「设置」→ 填 Base URL / API Key / 模型名 → 「测试连接」→ 保存（任意 OpenAI 兼容服务都行，如 DeepSeek）；
- 用完直接**关掉黑色窗口**就是停止服务。

### 常见问题

| 现象 | 解决 |
|---|---|
| 提示找不到 Python | 做第 1 步；装完重新双击 |
| 提示依赖安装失败 | 网络问题，稍后再双击；还不行删掉 `.venv` 文件夹重试 |
| 端口 8000 被占用 | 右键编辑 `一键启动.bat`，把 `--port 8000` 改成 `--port 8001`，浏览器访问 8001 |
| 想更新代码后重装依赖 | 删掉 `.venv\.deps_ok` 再双击 |

│   ├── novel/               #   正文子库：vectors.npy + meta.json（2335 条）

│   ├── quiz.json            #   题库
│   └── summaries.json       #   章节摘要原文
├── app/

│   ├── config.py            # .env 配置（支持网页里保存 Key；检索固定为 Jina）
│   └── static/              # 前端静态资源
├── scripts/
│   ├── build_wiki.py        # Jina 设定库 → 百科 data_jina2/wiki.json
│   ├── build_wiki_store.py  # 百科词条 → Jina 向量子库 wiki/

│   ├── generate_summaries.py# 批量生成章节摘要（调 LLM，可增量）

## 配置项（.env）

| 变量 | 默认 | 说明 |
|---|---|---|
| `AI_API_KEY` | 空 | OpenAI 兼容服务的 Key，留空时进入检索测试模式 |
| `AI_BASE_URL` | `https://api.deepseek.com` | OpenAI 兼容接口地址 |
| `AI_MODEL` | `deepseek-chat` | 服务商开放的模型 ID |
| `RAG_TOP_K` | `5` | 检索返回片段数（可调，见评估） |
| `RAG_EXCERPT_CHARS` | `600` | 每个片段送入模型的字数 |
| `RAG_DATA_DIR` | `data_jina2` | 保留用于兼容旧配置；运行时固定使用 Jina 目录 |
| `RAG_MODEL_CACHE_DIR` | `model_cache` | 本地 embedding 模型缓存 |

旧版 `DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL`、`DEEPSEEK_MODEL` 仍可读取；同一项同时存在时优先使用 `AI_*`。

## 资料包：分享与迁移资料

设置页的资料包操作针对的是资料，不是程序安装包，也不包含 API Key 或向量模型：

| 操作 | 包含内容 | 适用场景 |
|---|---|---|
| 导出资料包 | 百科、分类、默认题库、浏览器自定义题库与可用百科索引 | 分享资料、增量迁移 |
| 导入资料包 | 先展示文件清单、百科冲突和题库冲突 | 合并时保留本地冲突；覆盖时自动备份 |
| 完整离线包 | `data_jina2` 内的完整资料与索引 | 完整备份或整套资料迁移，仅支持覆盖导入 |

导入后，只有百科内容、模型和 `768` 维索引全部一致时，索引才能直接启用。合并了新词条或索引不匹配时，设置页会提示重建。

## 重建百科索引

项目固定使用 Jina 中文增强模型。编辑百科数据后执行：

```bash
python scripts/build_wiki_store.py
```

它只重建 `data_jina2/wiki/`，不会生成其他模型索引。

### 如何触发重建？

在百科页面新增、编辑、删除词条或合并资料包后，页面内容会立刻热加载；为了让 Jina RAG 的语义检索同步新资料，请在「设置」→「检索模型」中点击 **重建百科索引**。任务在后台运行，完成后会自动刷新检索器，不会修改 `wiki.json`。

也可以在项目根目录执行：

```bat
.venv\Scripts\python.exe scripts\build_wiki_store.py
```

脚本会读取 `data_jina2/wiki.json`，只重建 `data_jina2/wiki/meta.json` 和 `data_jina2/wiki/vectors.npy`。当前 2627 条百科词条在本机 CPU 上通常需要数分钟；如果不重建，运行时保护仍会过滤已删除词条，但新词条不会立即参与向量召回。

## 问答处理逻辑

系统按“**原文考据优先 → 资料性质判定 → Jina RAG → 联网兜底**”处理问题：

1. **首次出现 / 第几章**：按卷、章顺序扫描原著全文，直接返回卷章、行号和原文；不使用 RAG、不联网。
2. **连续文本片段**（如台词、诗句）：先原著全文精确检索。全书唯一命中时直接返回位置；多处命中时，把最早几处原文作为强制证据交给 RAG；原著无命中则继续查百科与资料合集。
3. **资料合集二创诗词**：精确命中时明确标记“书友二创 / 非原著”，不会把它说成原著正文，也不再联网猜测。
4. **剧情、人物、设定等普通问题**：固定使用 Jina 向量检索 + BM25 关键词检索，经 RRF 融合后，把正文、资料合集、摘要和百科证据交给 AI 回答。
5. **百科条目删除后**：运行时会核验条目是否仍存在于 `data_jina2/wiki.json`；删除词条不能再作为 RAG 来源。重建索引后会从向量库彻底清除。
6. **联网兜底**：仅在原著、百科/资料合集和本地 RAG 都没有可用证据，且设置中开启联网时使用；回答会明确标注为网络回答。

## 章节摘要（可选，提升剧情类问题检索）

1. 生成摘要：`python scripts/generate_summaries.py --vol 第1卷：魔性不改 --start 1 --end 199`（需要 .env 配置 key，会调 deepseek-chat 给每章写 150 字左右摘要，可增量续跑）
2. 建立摘要索引：`python scripts/build_summaries.py`（向量化 summaries.json 到 data_jina2/novel_sum/）
3. 重启服务生效。摘要数据与索引均保存在固定的 Jina 数据目录中。

## 评估检索质量

```bash
python scripts/eval_retrieval.py            # 内置测试集（15 题，或优先用 Jina testset.json）
python scripts/calib_testset.py            # 校准测试集：BM25 专名定位真实章节（30 题）
```

根据结果修改 `.env` 里的 `RAG_TOP_K`。检索模型固定为 Jina 中文增强版本，不提供切换。

### 固定检索模型

| 模型 | 查询耗时 | 说明 |
|---|---|---|
| **jina-v2-base-zh** | 约 0.033s/问 | 中文增强向量检索，项目唯一保留的检索库 |

- 参数结论：`k=5` 已足够；**RRF 混合检索比纯向量更适合小说专名场景**，关键词检索与语义检索共同参与排序。

## 构建 Windows 便携版

发行构建在 Windows PowerShell 中执行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/build_portable.ps1
```

脚本会校验当前 Jina 模型和索引，下载与当前 Python 版本匹配的官方嵌入式 Python 运行时，组装独立运行目录，并生成 `dist/GZR-portable-v1.0.0.zip`。发行目录不会复制 `.env`，因此不会包含本机 API Key。构建前应先完成百科编辑并重建索引。
